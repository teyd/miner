# miner

A headless Twitch drops miner for homelabs, built for other people too. TypeScript 7 on Node 26, Effect 4.1,
pnpm 12, Vite+ (`vp`). Status: the pure core, the read-only Twitch client, the config file, the simulator (`miner sim`), the
flight recorder, the runtime (`miner run`, and read-only `miner run --shadow`), the live actuator (watch over HLS,
`ClaimDrop`), PubSub and `miner status [--json]` are built. `miner run` mined and claimed for real on 2026-10-30 (research 02 §4).

- `src/bin.ts`: the entry point. It wires Node services into the CLI.
- `src/cli/`: Effect CLI commands. `miner.ts` is the root command, `doctor.ts` the read-only probe, `config.ts`
  `config schema|validate|init`, `journal.ts` `journal cat` (a recording with every answer whole), `run.ts` the runtime (live, or `--shadow`; both lock `$DATA_DIR/miner.lock`), `sim.ts` the simulator,
  `status.ts` reads `$DATA_DIR/status.json` and exits 0 healthy/starting, 1 not running, 2 needs login, 3 discovery broken.
- `src/config/`: `$DATA_DIR/config.json`. `schema.ts` decodes it and is the documentation agents read; `load.ts`
  reads and validates it. `schema/config.v1.json` is generated by `pnpm schema` and must be committed after any
  change to `schema.ts` (a test compares them). `schema/config.example.json` is the documented example.
- `src/platform/`: the IO shell, the only place besides `src/bin.ts` that may touch time,
  randomness, timers, network, env, console or Node built-ins. `logging.ts` is the logger (decision 29):
  stderr, pretty or JSON (`LOG_FORMAT`, `LOG_LEVEL`), redacted, plus a size-rotated JSON copy in
  `$DATA_DIR/logs` (`LOG_FILE`). Code logs with `Effect.log*`, `Effect.annotateLogs` and `Effect.withLogSpan`;
  command output for the user stays `Console.log` on stdout.
  `Gzip.ts` is sync `node:zlib` for the recorder (it reads past a member torn by a crash), `Sha256.ts` names
  recorded parts. `lock.ts` is the one-miner-per-`DATA_DIR` pid lock.
  `instance.ts` is the version and pid that `status.json` names.
- `src/runtime/`: runs the core for real. `run.ts` is the one scheduler fiber: it takes the next event or a `Tick`
  at `nextDeadline(state)`, steps, saves the state, then forks the step's commands, whose results come back as
  events. `execute.ts` turns a command into `Twitch`/`Actuator` calls (the simulator uses it too).
  `settings.ts` maps `config.json` to core `Settings` before every step (names and logins become ids as the
  catalog and channels arrive) and lists what `Settings` can't express yet (`unmapped`, logged at start).
  `shadow.ts` is the actuator of `run --shadow`: it records and logs what it would do and sends nothing.
  `live.ts` wires `miner run`: reads and mutations share one set of request budgets and one recorder, state in `state.json`.
  `status.ts` writes `$DATA_DIR/status.json` (tmp + rename, never fatal) from the run loop: on a change (at most
  every 2 s) and on a 30 s heartbeat, the loop's one wake-up besides the core's deadlines; a clean stop writes
  `stoppedAt`.
- `src/status/`: the external contract (decision 15). `schema.ts` is the versioned, documented Schema of
  `status.json` and of the `miner status --json` report; `schema/status.v1.json` is generated by `pnpm schema` and
  committed (a test compares them). `snapshot.ts` is pure: the document from `State` plus what the run observed
  (read times, claims settled this run), and `health`, the verdict and exit code.
- `src/store/`: `codec.ts` encodes `State` canonically with a schema version (another version is refused, never
  guessed); `Store.ts` saves it atomically (tmp, fsync, rename). `memoryFileSystem.ts` is a synchronous
  `FileSystem` for tests under `TestClock`.
- `src/core/`: the pure decision logic. `step(state, event, now)` in `step.ts` returns the next state and the
  commands to run (`protocol.ts`). `rules.ts` holds Twitch's earn and claim rules with their sources, `plan.ts`
  picks a drop and a channel. Contract for the runtime: persist the returned state before executing its
  commands, and wake the core at `nextDeadline(state)`. `fixtures.ts` builds test data.
- `src/twitch/`: the one Twitch seam. `Twitch.ts` is the service (validate, catalog, inventory, directory,
  streams, current drop), `wire.ts` decodes answers into core types, `identity.ts` holds every Twitch constant
  with its source and date. `budget.ts` holds the request budgets (critique CF-5), one per class: GQL (starts
  300 ms apart, at most 4 a second and 4 in flight, under ~5 GQL/s per IP) and CDN (one at a time, ≤ 480 a
  minute); sockets are bounded by `WATCHLIST_LIMIT` and `PUBSUB_MAX_CONNECTIONS`. A request waits for its turn
  at most `maxWait`, otherwise fails `BudgetExhausted` unsent, and a 429 cools the class down; the core gets a
  `Throttled` event and reschedules (a refused claim goes the lost-answer way: inventory decides).
  `journal.ts` is the flight recorder: answers and actuator intents, one gzip member per line, one file per UTC
  day in `$DATA_DIR/recordings/`, bounded by days kept, total bytes, bytes per day and a body cap; a failed
  write is logged, never fatal. An answer's parts (objects and arrays of 256+ JSON chars) are written once per
  file and then as `{"$same": "<hash>"}`; a reference only points back into the same file, at a line this
  process saw written (research 04 §3a). `expandRecording` restores the answers, `miner journal cat <file>`
  prints them. `redact.ts` removes secrets, and every line must pass `isSealed` (a fixed point
  of `redact`, without the token) before it is written. `fixtures/` are real answers recorded on 2026-10-28
  with identities replaced, plus `leaks.json`, real leak shapes the redaction tests use as inputs; `stub.ts`
  serves the answers to tests.
- `src/twitch/Actuator.ts`: the mutation seam (watch session, ticks, claims, subscriptions). `live.ts` is the real
  one: `claimDrop` sends `DropsPage_ClaimDropRewards` once, never retried; its `subscribe` does nothing, because
  `withListening` (`src/runtime/listen.ts`) routes every actuator's `subscribe` to PubSub. `hls.ts` is the watch method behind `WatchMethod` (token → usher →
  lowest media playlist → `HEAD` each segment per tick), swappable because Twitch changes it (research 02 §4);
  `playlist.ts` parses HLS. `gql.ts` is the one GQL exchange reads and mutations share.
- `src/twitch/PubSub.ts`: the socket to `wss://pubsub-edge.twitch.tv/v1` (research 02 §5). `subscribe` sends only
  the LISTEN/UNLISTEN difference over connections of at most 50 topics, each with its own Effect `Socket` (an
  Effect `Socket` writes to the websocket it opened last, so never share one). `frames.ts` decodes frames into
  core events; `events` feeds the run loop (`forwardFrames`). Listening is read-only, so `--shadow` listens too.
- `src/twin/`: the simulator (plan `docs/history/09-plan-twin.md`). A `Scenario` (`scenario.ts`) is plain data that
  fast-check generates and shrinks; `world.ts` is the twin's Twitch rules with sources; `calibration.ts` the timings
  measured on the 2026-10-30 recordings (research 04 §2b), which `calibration.test.ts` derives again from the relabelled
  `fixtures/calibration-2026-10-30.json`, and which scenarios draw from. The twin is Twitch's wire:
  `http.ts` serves GQL (reads, `PlaybackAccessToken`, the claim), and `cdn.ts` usher, playlists and segment
  `HEAD`s, crediting a watch only on a whole beat (a playlist and a `HEAD` of each of its segments); `edge.ts` is
  the PubSub edge behind a `WebSocketConstructor` (LISTEN/UNLISTEN, PING/PONG, RECONNECT, frames, 50 topics a
  socket, 10 sockets). `process.ts` runs the miner's own `liveServices` (`hlsWatch`, `ClaimDrop`, `PubSub` over
  `Connector.webSocket`) on it, one process per crash, within the run's request budgets (`budget.ts`), which
  the miner's own code charges; a `Plant` swaps a piece to prove the twin catches a bug.
  `sim.ts` is the loop (step, persist, check, execute) under `TestClock`; `invariants.ts` checks every
  step, the wire included (`Orphan`, `TokenLeak`, `SocketBudget`, `SocketChurn`, `NotListening`, `WatchMisread`).
  The twin enforces Twitch's per-IP limits (`twin.ts`: 429 above 5 GQL/s, at most 10 sockets) and
  `OverBudget` fails a run that goes over them or over the miner's own budgets; `otherGames` gives worlds
  catalogs as large as the live one, so discovery bursts happen. A `gql-cooldown` fault (begun by the
  first inventory answer that shows a drop to claim) and a short `gqlMaxWait` make the budgets refuse
  claims and channel reads; `ClaimLate` fails a claimable drop left
  unclaimed (`claimLiveness`), `RefusalDropped` a refused read never sent again, and `sim` prints how many
  seeds refused each command. Each seed runs twice and the trace digests must match. A failure prints a capsule to replay.
- `README.md` is the user's tutorial (token, config, running, logs, what needs a person). Change it
  with any user-visible change. `Dockerfile` and `compose.yaml` build and run the image (node alpine
  plus `dist/bin.mjs`, uid 1000, `/data`); `deploy/miner.service` is the systemd unit. Both stop on
  SIGINT or SIGTERM with exit 130. The image's `HEALTHCHECK` runs `miner status`.
- Not built yet: config reload while running, replay of recordings.
- `docs/history/10-plan-roadmap.md`: the running plan (waves A–E) and how every step is built, reviewed and merged.
- `docs/decisions.md`: settled answers. Read it before proposing anything. Don't reopen a decision without new evidence.
- `docs/research/`: dated research with sources. `docs/history/`: proposals and their critiques.

## Commands

- `pnpm install`. pnpm switches itself to the pinned 12.16.1 and installs Node 26.13.0 into
  `node_modules/.bin` (`devEngines` in `package.json`). Scripts run on that Node, whatever `node` is on PATH.
- Commits pass the secret guard's hooks (Shipping). `pnpm check` is the gate: `vp check` (format, lint, typecheck) and then `vp test`. CI runs exactly this
  plus `pnpm build`. Done means exit 0.
- `pnpm exec vp check --fix` formats and applies lint fixes. `pnpm exec vp test <file>` runs one test file.
- `pnpm build` bundles everything into `dist/bin.mjs` (`vp pack`). One file, no `node_modules` at runtime,
  because that halves idle RSS (research 03). `pnpm start --help` runs it.
- Environment comes from Varlock: `.env.schema` (committed) declares every variable, values go in `.env.local`
  (gitignored). `pnpm dev <command>` builds and runs the CLI with that environment (`varlock run`), e.g.
  `pnpm dev doctor [--json] [--record file.jsonl]`, which checks the token and reads the catalog and inventory,
  writing nothing to Twitch. `pnpm exec varlock load` validates the environment and masks secrets.
- `pnpm dev run --shadow` is a read-only live run: real token, real reads, real planning. Watch, subscribe and
  claim are recorded and logged as intents, never sent. State goes to `$DATA_DIR/state.shadow.json` (never
  the live state file: a shadow claim intent would block a real claim), recordings to `$DATA_DIR/recordings/`.
  It counts as the one live miner. `pnpm dev run` mines for real (watches, claims) with state in
  `$DATA_DIR/state.json`. Both take `$DATA_DIR/miner.lock`, so a second miner on the directory exits 1.
- Recordings read directly with `zless`, `zgrep` or `zcat <file> | jq`; a part seen earlier in the file shows as
  `{"$same": "<hash>"}`. `pnpm start journal cat <file> | jq` prints every answer whole (it reads plain
  `doctor --record` files too) and exits 1 if a reference has nothing to point at. It talks to nobody.
- `miner status [--json]` (`pnpm dev status`, so it sees the same `DATA_DIR` as `pnpm dev run`) reads `$DATA_DIR/status.json` only (live and shadow runs share it; `mode` says which wrote it), never Twitch, so it is safe
  beside a live miner. `--schema` prints the JSON Schema of `--json`. The exit code is the health check.
- The simulator: `pnpm build && pnpm start sim [--seed N] [--seeds N] [--json]` runs seeds 1–100 by default
  and exits 1 on any invariant violation, printing the shrunk capsule and the rerun command. Save a capsule to a
  file and `pnpm start sim --trace <file>` replays it. `MINER_SIM_SEED`, `MINER_SIM_SEEDS` and `MINER_SIM_TRACE`
  stand in for the flags. `pnpm exec vp test src/twin` runs its tests (seeds 1–20, 6 h horizons).
- Use `pnpm exec`, not `npx`: `devEngines` refuses npm.

## Code rules

- Lint enforces determinism. The `effecttsgo` rules for `Date`, `Math.random`, timers, `fetch`,
  `process.env`, `console` and Node built-in imports are errors outside `src/bin.ts` and `src/platform/`.
  Use `Clock`, `Random`, `Effect.sleep`, `HttpClient`, `Config` and `Effect.log`. Simulator seeds must
  replay exactly. Don't widen the override list to make a file pass.
- Core logic is pure: `(state, event, now)` in, `(state, commands)` out.
- Comment only what the code can't say: a Twitch quirk, a source, a non-obvious invariant. No doc comment
  that restates the name or type.
- Decode Twitch JSON at the boundary with Schema. A `null` where data belongs is an error, never a default.
- Import platform modules by path (`@effect/platform-node/NodeRuntime`), not from the package index.
- Tests sit next to the code as `*.test.ts` and use `@effect/vitest` (`it.effect`, `TestClock`, `TestConsole`).
- `effect-tsgo patch` runs on every install (`prepare`). If lint says `Unknown plugin: 'effecttsgo'`, run
  `pnpm install` again. `@effect/tsgo` supports exact oxlint and tsgolint versions, so it is bumped together
  with `vite-plus`.

## Twitch gotchas

- The API is private and undocumented. Hashes, client IDs and headers break about monthly. Re-verify before relying on one, and update the date in research 02.
- Twitch sometimes answers `null` with no error. Treat it as a failure.
- Limits are per IP (about 10 websockets, 5 GQL requests per second). Live runs use the account in `.env.local`,
  which is teyd's normal account (approved 2026-10-29): one live miner at a time, and keep request rates at what a
  person in a browser would cause.
- Never log out or revoke a token. Getting a new one needs a human in a browser.
- Never auto-retry a claim. A lost answer may still have succeeded, so read state first.
- Tokens, signed playlist URLs (`sig`, `token`, `hdnts`, `dna`), the `USER-IP` of a playlist, the `auth-token` cookie and
  `Authorization` headers never reach logs, fixtures or commits. The secret guard (Shipping) blocks their shapes.
- Never read, print or copy `.env.local` or any `.env.*` file. To check the token is set, run
  `pnpm exec varlock load`, which masks it. A new variable goes into `.env.schema` first, marked `@sensitive`
  if it's a secret.

## Shipping

- The default branch is `dev`. One worktree per task, never one inside another task's worktree. If you are
  already in a linked worktree (`git rev-parse --git-dir` differs from `--git-common-dir`, as when T3 Code
  made it), use it and run `scripts/worktree-setup.sh` once: it symlinks the main checkout's `.env.local`
  and installs. Otherwise `scripts/worktree.sh <type>/<task>` creates `.worktrees/<task>` from `dev` and
  runs the setup. Branch names are free-form (squash merge). Remove the worktree with whatever made it
  (`git worktree remove`, or the tool's delete) after merge.
- The secret guard. `pnpm install` installs git hooks with lefthook (`lefthook.yml`; `prepare` skips it outside git).
  pre-commit runs gitleaks on the staged changes (`.gitleaks.toml`: the default rules plus Twitch's shapes), refuses
  `data/`, `*.jsonl[.gz]` recordings and `.env*` other than `.env.schema`, and greps the staged files for the
  literal `TOKEN` from `.env.local` through Varlock (it prints only the file name, and skips without a `TOKEN`).
  commit-msg checks the message the same way, pre-push scans the whole history, and CI's `secrets` job scans it
  again. Hooks live in the shared `.git/hooks`, so they cover every worktree; one on a branch without
  `lefthook.yml` passes with a note. gitleaks comes from `mise.toml` (`mise install`); without mise or a
  `gitleaks` on PATH the commit fails. Full scan: `scripts/hooks/gitleaks.sh git --redact -v .`. Always pass
  `--redact`, or gitleaks prints the secret it found.
- On a hit: never `--no-verify` past it, never `gitleaks:allow` (ignored), and never allowlist a real secret.
  Remove it from the change. A real secret that was ever committed, even locally and amended away, is burned:
  rotate it (only teyd can: a new Twitch token needs a browser login), then rewrite the history before any push.
  A false positive gets an allowlist entry in `.gitleaks.toml` scoped to one path and the fake value, as the
  existing ones are; fake secrets in tests contain the word `SECRET`.
- PRs target `dev`. Squash merge. The PR title becomes the commit: `feat(scope): …`, `fix(scope): …`, `docs: …`.
- The PR body gives the user-visible change first, then design notes with file paths, then the commands you ran and their output.
